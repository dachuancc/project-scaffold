# 架构决策记录（ADR-lite）— {{PROJECT_NAME}}

> 每个关键决策一条，编号递增，**只增不改**。
> 要推翻旧决策，**不要删旧的**，而是新增一条说明「取代 D<n>」并写清理由——
> 这样接手的人能看到演进过程，不会重复踩坑。

**怎么判断该写一条**：如果这个决定「改起来代价大」或者「看起来可以用别的做法」，就值得写。

**两种详略，按决策分量选用**（格式参考 [MADR](https://adr.github.io/madr/)）：

| | 简版 | 全版 |
|---|---|---|
| **适用** | 局部、易改的技术选择 | 改起来代价大、或别人很可能想推翻的决策 |
| **必填** | 决定 / 理由 / 影响 | 再加：决策驱动力 / 考虑过的其他选项 / 验证方式 |

> 💡 **写「考虑过的其他选项」是本文件最大的价值。**
> 只写「为什么选 A」，接手的人就会把 B/C/D 重新提一遍。
> 写下「为什么不选 B/C/D」，才真正拦住了重复讨论。
